# Redesign: the design brief

**Status.** Sections 1 to 8 are the original draft, written before the mock was built. Section 9 and the numbered decisions after it are what was agreed while the mock grew, and they win wherever they differ from the draft (for example the pill has no Finish day button, the dashboard is 1100 by 720, and there is no Hours table, Entries or theme editor). The mock itself, in `docs/redesign/mock/`, is the picture. It is a set of Design canvas boards that open in the canvas, not in a browser: https://claude.ai/artifact/5rsmaa9K1jvdpW9vwvJmUQ (private to the owner). `STAGES.md` is the build plan and says what has been done.

Draft 2, written from the three mock-ups and your notes. No code has been written. Items marked **Decision** need your call before work starts.

## 1. What we are building

1. A **small vertical pill** (mock-up 1): two status dots, the clock stacked as hours, minutes and seconds, play/pause, break, and Finish day. Hover shows the accounts; clicking opens a slide-out accounts panel.
2. The same pill **opens into the dashboard**. The dashboard's left rail is the pill's expanded form and runs the full height of the window. The rail gains the navigation buttons.
3. A **new Timeline page**: a horizontal timeline with gradient blocks and a now marker, planned meetings drawn as dashed cards above the blocks, a "Selected block" card and a day-notes card under it.
4. **Notes v2**, kept small: day notes in the timeline view, with add, remove and change the time or date of a reminder. Meetings and tasks start as dashed timeline cards.

Not in this work: tags, linked items, Month view, search, macOS window dots, and block-attached notes.

## 2. The pill

```
 ┌─────┐   two dots: left = recording state, right = notifications
 │ ● ● │   left:  grey idle · green running · amber break · red overtime
 │ 04  │   right: off, or blue and pulsing when a reminder is due
 │ 47  │
 │ 35  │   clock stacked, HH / MM / SS
 │ (▶) │   play / pause
 │ (☕) │   start / end break
 │  ⚑  │   Finish day / Start day
 └─────┘   about 72 wide by 330 tall at 100%
```

- **States:** the app already derives Recording, Break and Overtime pill colours, so the glow rings reuse them. Idle has no glow.
- **Hover (peek):** the pill shows account chips (colour, name, today's time, "+4 more") beside it.
- **Click:** a 240px accounts panel slides out over whatever is behind it, with today's time, a budget bar and Manage accounts.
- **How it is built:** the peek and panel are popups beside the pill, not a wider window. Today's pill code deliberately never changes the window's width, and a popup keeps that true. The popup flips to the left near a screen's right edge. A short grace timer stops it flickering shut as the pointer crosses the gap.
- **Existing pill settings:** Pill size (50 to 120 per cent) and the automatic scale-down on small screens carry over unchanged.

**Decision 1: the old horizontal layouts.** Add Vertical as a fourth layout and make it the default, or retire Full, Compact and Minimal now? I recommend adding Vertical and deciding about the old ones later, because that is the smaller change.

## 3. The dashboard shell

```
 ┌──┬───────────────────────────────────────────────┐
 │● ●│ Today   ‹ Thu 22 Oct › [Today]        [ … ]  │
 │04 │───────────────────────────────────────────────│
 │47 │ 08:00 09:00 10:00 …  [meetings, dashed]      │
 │35 │ [██ DLA ██][ ION ][ Nardello ] 🍴 [Hawthorn]  │
 │▶  │ + Add time block                              │
 │☕ │───────────────────────────────────────────────│
 │⌂  │ Selected block              │ Notes (2) + Add │
 │▦  │  DLA Piper 1h 30m 09:00–10:30 [Edit][…]       │
 │☰  │  Project planning             │ note cards     │
 │⚙  │                               │                │
 │⚑  │                               │                │
 └──┴───────────────────────────────────────────────┘
   rail runs the full height; the content area runs to the right edge
```

- **Window:** the dashboard opens in the pill's place, with the rail where the pill was. Pill and dashboard stay two windows, because resizing a visible window is something this app avoids. The pill hides while the dashboard is open, as it does today.
- **Rail:** pill controls, then the current destinations only (Timeline, Week overview, Hours table, Entries), then Settings and Finish day. Nothing new is added.
- **The 340px account column goes.** Accounts come from the same hover and slide-out panel as the pill, so budgets are still one click away.
- **Default size:** 1100 by 720 instead of 1080 by 680. That is enough for about ten working hours across the timeline at roughly 90px an hour, and it still fits a 1366 by 768 screen.
- **Header:** the title, date arrows, calendar date picker, Today and a "…" menu. Search and Month are left out. Week overview stays a rail button, so the Day/Week/Month control would only duplicate it.

**Decision 2: Day/Week control.** Leave it out for now (recommended), or add Day and Week only?

## 4. The Timeline page

- **Axis:** hours run left to right. The default window is the working day with a margin, with Ctrl+wheel zoom and horizontal scroll kept.
- **Blocks:** gradient fills derived from each account's colour. Each shows the duration in bold, the account, and "• first line of the entry note", with a small page icon when a note exists. Breaks are hatched with a cup icon. Short blocks show colour only, with a tooltip.
- **Overlaps:** blocks that overlap (older data can) stack on a second row, as lanes do today.
- **Now marker:** a vertical line with a time chip. **Decision 3:** the mock-up uses red, but red means overtime only. I recommend the accent blue unless you prefer red.
- **Add time block:** the dashed bar under the timeline opens the existing Add time dialog.
- **Moved controls:** Undo and zoom go in the "…" menu or beside the timeline. Merge and Edit move into the Selected block card.
- **Selected block card:** account dot, name, duration, span, Edit and "…", and the entry note as an editable line. It shows only what exists today.
- **Planned meetings:** dashed cards on a lane above the blocks, with a calendar icon and times, like the earlier meeting lane. They are never counted as tracked time.

## 5. Notes v2 (restricted, as you described)

- **Notes card:** the selected day's notes, with "+ Add note" and "Notes (n)". Each note has text, an optional date and time as its reminder, and a remove button. That is the whole feature set to start with.
- **Reminders:** a due reminder pulses the blue dot on the pill and the rail. The pill shows no reminder text for now.
- **Meetings:** a note with a start and end becomes a dashed card on the timeline. Asking "did it take place?" is out of this first cut.
- **Tasks:** shown in the Notes card only. **Decision 4:** should a task with a time also show as a small marker on the timeline? I recommend no for now.
- **Storage:** the existing 0.5.0 shared packages already hold notes, times, meetings and the kinds. No package release is needed.

## 6. Look and feel

- **Gradients:** the app has none today. They are derived on the desktop side from each account colour, without changing the shared packages.
- **Surfaces:** a very soft background tint, rounded cards (around 16px) with gentle shadows, and a dark glossy pill in both Light and Dark.
- **Contrast tests:** the existing contrast tests keep applying, so the new look has to pass them in every built-in theme.

## 8. Risks

- **Screen scale:** the pill is drawn at 70 to 85 per cent on small screens and the dashboard is not. The rail would look bigger than the pill it replaces unless the two scale together.
- **Hover flicker:** the peek and panel need careful pointer handling, and I can't check hover timing on real Windows from here.
- **Horizontal timeline:** this is the biggest piece of work, and its gestures are the most delicate code in the app.
- **Headless screenshots:** they use Linux fonts, so they are close to the real rendering but not identical.
