# Avalonia migration build

The `migration` branch starts from experimental v2.32. Its original PowerShell launcher still runs the existing application. This directory contains the separate Avalonia replacement under development.

## Try the Windows build

Download **BasicsAdvancedTimer-Windows-preview** from the latest successful **Avalonia migration preview** GitHub Actions run. Extract the whole ZIP into its own folder and run `BasicsAdvancedTimer.Preview.exe`. Keep its DLLs and native libraries together. The package includes the .NET runtime and runs with ordinary user privileges, without an installer or separately installed SDK/runtime.

This stage now records real sessions. By default it creates **migration-data** beside the executable. Accounts and totals start empty; the earlier illustrative timesheet is no longer seeded into the app. Three initial account names are provided; change visibility, add accounts and configure budgets through Settings → Accounts and budgets.

The main clock shows elapsed working-day time, from the configured or early/manual start. It continues when accounts are paused or switched, and excludes Lunch and finished-day intervals. It continues counting beyond the scheduled finish, with overtime shown separately in red. Account rows count only their own credited time. Usual scheduled starts still take effect automatically, matching the PowerShell application. Start day allows early starts and resumes finished days; starting an account starts/resumes the day too.

Theme options are under **Settings > Appearance**, and also available by right-clicking either window. Choose System, Light or Dark. Hours format is in Settings. Not tracking is grey; overtime is independent and red. Budget rings use the configured week/month/quarter period.

The pill and fixed dashboard share one tracking model. Drag anywhere across the pill header, or drag the dashboard's date header, to move the window. Timeline and Week now use recorded sessions and credited totals. Sessions crossing midnight are split; overlapping timeline entries use separate lanes. Timeline scroll is retained during periodic updates.

## Test copied existing data

Close the old application, then copy its settings, `Timesheets` directory and recovery/away files into a **separate data-only folder**, keeping the originals. Launch the new executable with:

```powershell
.\BasicsAdvancedTimer.Preview.exe --data-dir "C:\Users\YourName\Documents\Timer migration test"
```

The app refuses the old application folder when its script or launcher is present. A folder lock prevents two new builds using the same data folder. Do not run the old app against the migration copy simultaneously; the old process does not participate in the new lock.

The storage adapter reads the existing schema-1 JSON sections, account visibility, budget periods, weekday shifts, days off, manual starts, CSV credited rows and away intervals. It preserves unknown settings sections/root properties and extra CSV columns. Notes now load and save in their existing CSV format. Editing a source interval prunes obsolete group references. Credit positions and grouping metadata now load in the existing formats. Legacy merged credit contributes to totals; placing that credit draws intervals without adding ledger rows. Legacy Undo files and exports remain in place.

Sessions, manual starts, away intervals, preferences and crash recovery are saved together through an atomic write-ahead journal. Interrupted saves replay before loading. Files receive `.bak` copies. Active sessions checkpoint every 15 seconds and stop/save on a normal close. Crash recovery credits only up to the last successful checkpoint, not the time the app was closed. A save failure keeps pending time in memory, shows an error, retries, and prevents ordinary closing until saving succeeds. Invalid settings/CSV stop startup rather than resetting data.

## Current scope

Connected: start with Windows, tray icon, account renaming and reordering, day/account/lunch tracking, early starts, finish/resume, overtime, copied settings/CSV loading, new session saving, crash recovery, account visibility and budget editing, budget period totals, theme and format persistence, recorded Timeline/Week display, entry editing and notes, gap additions, deletion, persistent Undo, credit positioning/grouping, reviewed Tidy day and reconciled weekly CSV exports.

Still to migrate: overnight shifts. Stopped weekly decimal values use the same reconciled hundredths as export; running totals are provisional. This remains a migration build for testing, rather than the complete replacement for everyday timesheets.

## Architecture and checks

- `Timer.Core` is platform-independent C# for schedules, day calculations, credited sessions and recovery.
- `Timer.Storage` adapts existing files, locking, backups and recoverable saves.
- `Timer.Desktop` supplies Avalonia views, shared theme resources and the application model. It has no duplicate timekeeping rules.

The build uses .NET 8 and pinned Avalonia 11.3.16. SDK/NuGet dependencies are needed to develop it, not to run the packaged Windows build.

```sh
dotnet run --project migration/src/Timer.Desktop/Timer.Desktop.csproj
dotnet test migration/tests/Timer.Desktop.Tests/Timer.Desktop.Tests.csproj --configuration Release
dotnet publish migration/src/Timer.Desktop/Timer.Desktop.csproj --configuration Release --runtime win-x64 --self-contained true -o artifacts/windows-preview
```

Tests use disposable synthetic data only. Core checks exercise early starts, account pauses, lunch, finish/resume, overtime, days off, midnight splitting and credited adjustments. Storage checks cover copied legacy formats, unknown-field preservation, locking, checkpoint recovery, journal replay and malformed-file handling. UI checks use production styles/fonts/windows, drawn row positions, shared formats and view switching. CI checks Windows, Linux and macOS, uploads rendered previews, and starts the published Windows executable with an isolated temporary store. Native DPI transitions, tray behaviour and the intended work-machine launch still need desktop checks.

### UI review and sample data

The compact pill follows the original layout: timer on the left, account and today’s credit in the middle, pause/resume on the right. Click the account area to show or hide its account list. Click the timer to open the dashboard, and use Back to pill to return. Hold LMB and move at least five display-independent pixels anywhere across the pill header, including its timer, account or pause control, to drag it without activating that control. Release without dragging to click. The dashboard moves by dragging its header text or empty header space. Header buttons remain clickable. The main clock turns green while tracking and grey while idle; overtime has its own red label. Pause/resume retains the selected account and does not stop the day clock.

Run **Start-Demo.cmd** from the Windows preview folder, or choose **Settings → Open sample-data demo**. Demo mode has seven accounts with week, month and quarter budgets (one comfortable, one nearly used, one over, and two with none), a few days of history and today's intervals, so long lists can be tried at a realistic size. It uses a simulated 14:15 clock on today's date, advances in real time, and never opens or saves personal data. Inside the demo, the right-click menu has a **Test overtime** switch, next to where Open sample-data demo sits in a normal run. Ticking it ends today's shift at 13:00 so the day is in overtime, and unticking it puts the usual shift back, so you can test both the pill's red overtime theme and the return to normal. It is only available in the demo. CLI: `--demo` (cannot be combined with `--data-dir`).

**Settings → Working hours** edits each weekday's working status, start and end. These changes persist in normal mode. The optional “Also reset today” checkbox removes today's exceptional start/shift so the new schedule applies; it does not change account records or finished-day breaks. Overnight shifts remain unsupported at this stage. Copied-data imports still require `--data-dir` as described above; normal launch starts with your migration-data folder, without synthetic records.

**Settings → Accounts and budgets** adds accounts, hides/shows existing accounts and edits their week/month/quarter budgets. Budget hours accept decimals such as 7.5; blank means no budget. Hiding the active account first stops and saves its current session. Hidden accounts remain in Timeline and Week history, and showing one again restores its tracking row and credited totals. Edit an account's name in the same window to rename it. When you save, you choose between **Rename past entries**, which moves all recorded time, notes, groups, positioned credit and the budget to the new name after saving a backup copy under `Timesheets/Backups`, and **Start afresh from now**, which leaves the past entries under the old name as a separate historical account. Renaming past entries clears the Undo history, because older steps would put the old name back. A new name that already appears in the history, or on another account, is refused so two accounts are never combined by accident, and a renamed account that is running is stopped and saved first. Accounts cannot be deleted, only hidden. Break is built in and reserved, so no account can use that name.

**Week tabs.** The dashboard has one row of tabs, Timeline, Overview, Hours table and Entries, so the week is split into three parts and no single screen is a wall of numbers. Add time, Undo and Merge appear only where they apply (Merge once blocks are selected), and Tools stays on the right. **Overview** shows the week's worked, break and unallocated totals, a bar for each working day split by account colour (hover a bar for its figures), and one line per account with its week total and, when it has a budget, a meter that turns amber from 80% and red from 100%. **Hours table** has the full figures: account rows, a bold total excluding breaks, and faint Break and Unallocated rows, then the budgets table. Times are short (7:00, or 7.00 in decimal) with a dash where nothing was recorded, so seven days fit the width. **Copy hours table** copies the same table as tab separated text with the full wording (7h 00m), ready to paste into a timesheet. **Entries** lists every entry for selecting, merging, editing and moving. The arrows, and the Left and Right arrow keys, move a whole week in the Week tab and stop at the current week, and move a day in Timeline. The gap between the arrows stays the same whatever the text says. Right-click an entry, in Timeline or Week, and choose **Move to account** to move it, with its note, to another account as one undoable edit. When the entry you click is selected, every selected block moves. Merged credit cannot be moved, and a move is refused if the other account already has an entry starting at the same time.

**Pill and clock details.** The expanded pill ends with one wide, filled Start day (green) or Finish day (red) button, and the dashboard's day button turns to a red outline when it would finish the day. Both use the theme's Finish colour. The expanded pill only has a scroll bar when the screen is too short to show all the accounts. It, and it is exactly as tall as its accounts need, with no dead space. Settings are on the right-click menu. The pill's shadow and glow fade into each other when you press play or pause.

**Timeline controls.** A small bar floats over the timeline's top right with three icons, each with a tooltip: zoom out, zoom in and fit the day. Fit zooms and scrolls so the day's recorded time, with a quarter of an hour either side, fills the window, using the working day when nothing is recorded. The zoom icons dim at the limits (60 to 640 pixels per hour). Ctrl and the mouse wheel still zoom. Tidy day stays in Tools. **Account order animations.** While you drag an account, the rows it passes slide aside, and on release it glides into its new place, or back to where it was if you let go where you started.

**Account colours.** Every account is given the first of eight soft colours that no other account uses, once, and the colour is saved with the account in the settings file (a third part after the name and hidden flag, which older timers ignore). Existing accounts are coloured in their current order, so nothing changes at first. Past eight accounts the colours repeat. Choosing your own colour is planned with the data format work.

**Delete and the grip.** Right-click a block in Timeline, or an entry in Week, and **Delete** is the last item, below a separator. It deletes that block, or the whole selection when the block you clicked is selected, as one undoable edit, the same as Backspace. Each account row in the dashboard list has a grip of six dots at its left to show it can be dragged to a new place; the pill's list cannot be reordered, so it has none.

**Adjust time today.** Right-click an account in the dashboard list or the expanded pill and choose **Adjust time today** to add or remove minutes on that account for the day without touching any recorded block. Type +15, -10, 1:30 or 7.5 (minutes), or use the quick buttons; the dialog previews the account's new total and takes an optional note. It cannot take off more than the account has that day. The adjustment counts in the account's totals, the unallocated figure, the week table and the export (as an Adjustment entry), and shows on the Timeline as a chip above the hours, such as Account one +0:20, with its note on hover. Double-click a chip to edit the note, or right-click it to delete the adjustment. It is one undoable edit, and is stored as an adjusted row in the time file. The account menu also has Name and budget, below a separator. The window's right-click menu is ordered by use: hours format, accounts and working hours, then appearance, shadows and start with Windows, then the demo, and Close timer alone at the bottom.

**Break.** A break is a pause of any kind, and it stops time going to every account. It has its own button, apart from the account rows and wearing the amber break colour. On the dashboard it sits in the sidebar above the day totals, as Take a break and then End break. On the pill it is the cup button beside pause. Ending a break, with either button or with the pill's resume button, goes back to the account that was running when the break began. If nothing was running, ending it leaves nothing running. While a break is on, the pill turns amber and glows amber, the steam above the cup moves, the dashboard's break button turns amber, and the running block on the timeline is labelled Break. The dashboard keeps its normal colours. Breaks do not count towards the working day, an account or the budget rings, as lunch did before. They are still stored under the name Lunch in `sessions.csv`, so existing files keep their meaning, and shown as Break everywhere, including the entry editor and the week export. A later change to the data format will turn them into proper break entries.

**Tray.** The timer has no taskbar button and lives in the notification area. Neither window has a close button, so it cannot be closed by accident. Left-clicking the tray icon hides it there, Alt+F4 does the same, and tracking carries on. The icon is green while recording and slate otherwise, and its hover text shows the account, the day's time and any overtime. Left-click shows the timer, or hides it when it is already in front. Right-click offers Show timer, Dashboard, Pause or Resume, Start or Finish day, Reset position (top right of the main screen, which also recovers a window left on a disconnected monitor) and Close timer, which saves and quits. Close timer is at the bottom of the Settings and right-click menus, apart from everyday actions, in case Windows keeps the icon in the hidden-icons overflow. Starting the program a second time reports that the data folder is in use, so look for the tray icon first. Windows shutting down still saves and closes normally.

**Look and feel.** Times use fixed-width digits, so clocks and totals do not shift their neighbours as numbers change. The pill always shows a thin line along its main row for how far through the working day it is, turning red in overtime and amber on a break; on a day off it is an empty track. The pill glows for a break (amber), overtime (red) and not tracking (grey), and the live dot pulses beside the account that is recording, in the pill and in the dashboard list. Both windows cast a soft shadow, which Settings, Window shadows turns off. While a break is on, the pill shifts to an amber theme, and in overtime it shifts to red. The dashboard keeps its normal colours. If both apply the break wins, because it is the state you chose just now, and overtime wins over normal. Not tracking has no tint of its own, so it shows through the grey glow and cannot clash with the other two. All of these colours come from the shared theme file (`App.axaml`: Live, Idle, Overtime, Break and ShadowColor, with BreakLight, BreakDark, OvertimeLight and OvertimeDark variants), so future themes only need to define those names.

**Start with Windows** is a checkbox in the Settings menu. It adds a per-user entry to the Windows sign-in list (the `Run` registry key), so it needs no administrator rights or installer, and unticking removes it. The timer then opens, showing the pill, whenever you sign in. If you launched it with `--data-dir`, that folder is remembered. The box counts as ticked only while the saved entry points at the program you are running now, so after moving the folder it shows as unticked until you tick it again. The option is hidden in the demo and when the program is run through the `dotnet` command.

**Reorder accounts** by dragging a row up or down in the dashboard list. The rows it passes slide aside, Lunch stays at the bottom, hidden accounts keep their places, and a plain click still starts or stops tracking. Each account keeps its colour for good, so its blocks look the same on the timeline however you reorder, hide or rename accounts.

### Editing recorded time

Double-click or right-click a completed timeline block to open its entry editor. Change account, start/end time or note; delete is available for normal positioned entries. Notes can span lines and contain commas/quotes. Week now includes an individual entries list beneath the totals, including merged credit and adjustments (notes only). The block that is recording now has a green outline and a Recording now label. It is read-only until tracking stops, and clicking it says so.

Drag a completed timeline block to move it, or its top or bottom eight-pixel edge to resize it. Dragging an edge across the other one leaves a block of at least one minute. Movement snaps to five minutes away from neighbours and to their boundaries when close. Small overshoots stop against the neighbour; dragging a whole block more than 24 display-independent pixels past it inserts the block between the ones it crosses, which move into the space left behind. Durations and notes are kept and the whole move is one undoable edit; moves blocked by midnight, positioned credit, running time or unresolved imported overlaps apply nothing. Blocks shorter than 24 pixels split their height between the two edges, and the shortest only resize, so zoom in to move them. Overlaps and intervals shorter than three seconds are rejected. Future entries are allowed and credited immediately. Existing imported overlaps can keep their notes, but editing their times must resolve any conflict. Double-click or right-click free timeline space, or choose **Add time** to add new credited time in a gap. This increases the ledger total; it does not position old merged credit. Start/end accept HH:mm or HH:mm:ss; 24:00 is accepted as a day's end. Cross-midnight manual intervals must be entered separately for each day.

**Undo** reverses the most recent time/note edit, addition or deletion, up to 50 steps. The history persists across restart and keeps sessions recorded after an edit. Each step stores only the rows and the notes, group and position lines that edit changed, not a copy of the whole ledger, so the history stays a few tens of kilobytes however many entries there are, and it is also limited to about 2 MB, dropping the oldest steps first. Undo is offered only while the ledger, notes, groups and positions still match what the last edit left behind, so a file changed outside the app disables it rather than being overwritten. History written by earlier migration builds is imported as its latest step only. Saving writes only the files whose content changed, so a quiet 15 second checkpoint no longer rewrites the ledger, settings and edit history. Sessions, notes, credit positions, group metadata and edit history are journalled together; a failed save retains the in-memory change for retry. CSV extra columns survive edits and Undo. A changed source interval loses its old grouping reference, restored by Undo. Ambiguous legacy note keys (duplicate account/date/start) are protected from individual editing. The new Undo history uses migration-edit-state.json; old PowerShell Undo files remain untouched.

### Credit review, Tidy day and exports

The dashboard **Tools** menu contains **Position existing credit**, **Group entries**, **Tidy day** and **Export week**.

Position existing credit selects an account's remaining merged credit for the selected day, a start time, minutes and a position note. It preserves credited sessions and totals. Positioned credit has an outlined timeline block: double-click or right-click to edit or **Unplace** it. Unplacing returns the minutes to the available pool. Positions use the compatible `Timesheets/credit-positions.csv` format, including older files without a Note column. Future placements are allowed; overlaps and crossing midnight are rejected. The timeline caption shows remaining unplaced credit.

Group entries lists the selected week and selects at least two source entries for one account/day. New merges fill blank gaps with “Added by merge” credited entries and show a combined total in Week and on the timeline. Original source entries remain intact. Undo removes the gap fills and restores the prior group; Ungroup keeps the newly credited gap entries. Imported groups that still contain gaps show separate linked sections, preserving those gaps. Click a group to inspect/edit its parts, right-click to ungroup, or use the visible Ungroup button beside its Week entry. Tools → Group entries also lists existing groups. Editing a grouped source prunes its obsolete reference and any remaining singleton group; Undo restores it.

Tidy day previews gaps up to five minutes by default (adjustable 1–60). Choose the previous or next account for each gap, or leave it unfilled. Lunch, away intervals, future gaps, ambiguous boundaries and running entries are excluded. Applying rechecks the complete preview before adding credited time; a changed preview adds nothing. One Undo reverses the selected batch. Fractional boundaries are rounded inward so a fill cannot overlap adjacent entries.

Export week creates **Detail.csv** and **Summary.csv** together in a new folder under `migration-data/Timesheets/Exports` (or the selected copied data folder). Existing exports are retained. The dialog shows the saved folder path. Demo/test exports use a temporary folder. Exports include saved entries only: pause first to include the current active interval. Detail includes positions, unplaced credit, groups, adjustments and notes, excluding Lunch to match the working total. Summary includes hidden/historical accounts and a total excluding Lunch. Integer hundredths are reconciled across entries, account/day cells and grand totals, including negative adjustments. Positions and groups never duplicate credited time in exports.

The dashboard now has the same transparent rounded window surface as the pill. Scrollbars use an eight-pixel track and a slim draggable thumb, without arrow buttons.

### Select and merge blocks

**Click** completed Timeline blocks or Week entries to toggle selection. Selected blocks have a visible outline. Choose **Merge** in the dashboard toolbar or **right-click → Merge selected**. Release without dragging to select; dragging moves/resizes instead. Right-click offers editing/inspection and merging; double-click a timeline block to open its editor. Press Escape to clear selection; changing dates clears it too. Clicking empty timeline space clears selection. Press Backspace or Delete to remove the selected blocks as one undoable edit.

Merging requires blocks for the same account and day, with only blank gaps between them. Blank gaps are added as credited entries for that account and included in the combined total; the selection hint shows the added amount before merging. Overlaps, intervening entries, positioned credit and running time prevent a merge. Gap fills use whole-second starts and the ledger’s 0.01-minute precision, rounded inward to avoid overlap. Existing groups may be selected with other blocks to extend the group. Original source rows remain intact; one Undo removes the added gap time and restores prior grouping. Ungroup retains the newly credited gap entries. Older nonconsecutive groups render as separate linked timeline sections, without filling their gaps visually.

**Double-click empty timeline space** to add a block. A single click only clears the selection. The entry editor opens at the clicked time, snapped to five minutes, with a proposed 30-minute duration capped at the next occupied interval or midnight. Change the account, end and note, then Save. Clicking occupied blocks retains their normal edit/drag/selection behaviour. Only one entry editor opens at a time.
