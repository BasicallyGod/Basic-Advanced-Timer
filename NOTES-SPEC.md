# Notes: behaviour and design record

This is the specification of the Notes work built on `experimental` between 16 and 22 October 2026 and then removed so Notes could be rebuilt from a clean base. The code is on the branch `archive/notes-v1` (the last `experimental` build that had it, `4557363`). Pull requests 83 to 115 in `BasicallyGod/Basic-Advanced-Timer` hold the history. Nothing here is current code: it is what the rebuilt Notes should keep, change or argue with.

The paragraphs below were the Notes and Quick capture sections of `CLAUDE.md` when it was removed, unchanged. Names such as `NotesPage` and `NoteDetails` refer to the archived code.

## What the user asked for, in order

1. Raise Notes above Hours table and Entries on the rail, keeping those two for people who want them (Timeline, Notes, Week overview, then a divider, then Hours table and Entries).
2. Meetings as tentative blocks on the timeline: a note typed `14:00 - 15:30`, shown as planned time that is clearly not tracked and never counted, with a reminder, and a question once it ends (did it take place, and move it to tracked time). Ask which account, ask only once.
3. Recurring meetings: about 8 weeks ahead, "this one only" and "this and all later", and a No answer skips only that day.
4. From the second round of screenshots: details in a flyout, notes as one line, solid blue on Add note and Save only, upcoming reminders on the pill as a setting off by default, "+N more" in the reminder row, and a bell with one list of everything waiting.
5. Left out on purpose: a Recent or informational notification type, "Join" on meetings, the week-overview hover tooltip, a Windows toast notification.

## Behaviour (as it stood)

- Notes (`NotesPage` in `NotesView.cs`, the `NotesTab` button, second on the rail, in the top group with Timeline and Week overview (Hours table and Entries sit below a divider), `DashboardWindow.ShowNotes`, `notesMode`) is a page like Settings: built once when it opens and not rebuilt on model changes, because it listens to the model itself and rebuilds only when what it shows changed (`Signature`), so clock ticks do not replace rows under the pointer. It shows the notes for `TimerModel.SelectedDate` (the date arrows still work) beside Coming up (`ComingUpView`). A note is typed in the shorthand from `Timer.Core` (`NoteShorthand`: a time such as 14:30, `@fri` or `@tomorrow` for a day, a leading `!` for a deadline, `#AccountOne` linking an account through `AccountTags`), and the shorthand still works in the quick box at the foot of the page (`NoteInput`, watermark "Quick add"), but nothing depends on it: Add item (`NoteAddButton`) and each row's Details (`NoteDetails_<id>`, shown on hover) open the same themed anchored flyout (`NoteEditorDialog`, using the dashboard `DialogHost` without its dimmed backdrop) (`NoteDetails` in `NoteDetails.cs`, built each time it opens) with a Task, Meeting or Deadline switch (`NoteKind_Task`, `_Meeting`, `_Deadline`), the words, the day (arrows and an inline calendar, never a second pop-up inside the flyout), start and end (`NoteDetailsStart`, `NoteDetailsEnd`, HH:mm), the account, Repeat (Never, Every day, Every weekday, Every week, Every 2 weeks, or Choose days, with `NoteDetailsUntil`), and for a note in a series Apply changes to This one only or This and all later (only the second can change the repeat), then Save or Add (`NoteDetailsSave`, `NoteDetailsAdd`) and Remove… (a series asks which). `TimerModel.AddNote`/`SaveNote` take a `NoteEdit` and return what is wrong (a meeting needs a start, an optional end must follow it, times as HH:mm) or null. A row permits two title lines ( tick box, words, then quiet marks on the right: `NoteTime_<id>`, a flag `NoteDeadlineMark_<id>`, the repeat mark `NoteRepeatMark_<id>`, and the account's dot `NoteAccountMark_<id>`; the Details and remove buttons carry the `hoverReveal` class). The words box shows the words without the `!` and the `#Tag` (`NoteShorthand.Display`) and `SetDayNoteWords` puts them back around what is typed. The crosses and the move-day calendar are gone from the row (the day is changed in Details; `ClearNoteTime`, `ClearNoteDeadline` and `ClearNoteAccount` stay on the model). The remove and Details buttons (the `hoverReveal` class; `Ui.RevealOnHover` puts a `revealing` class on the row) show only while the row is under the pointer or has focus, so a list of notes is words first. The headings in both cards are plain semibold text, not the display face, and Coming up is grouped under a heading per day with each row showing only its time. Each note has a tick box (`NoteTick_<id>`), editable words (`NoteText_<id>`) and a remove button (`NoteRemove_<id>`). Notes live in the database (`day_notes`, outside the undo history) through `TimerModel` (`AddDayNote`, `NotesOn`, `ComingUp`, `ClearNoteTime`, `ClearNoteDeadline`, `ClearNoteAccount`, `MoveDayNote`, `ToggleDayNote`, `SetDayNoteText`, `RemoveDayNote`), and `SetAccounts` rewrites a renamed account's tags and turns a deleted account's into plain words. Account-coloured tag text uses `TagColours.Text`. Typing a `#` in the add box (and in Quick capture) lists the accounts that match (`TagPicker`, `TagSuggestions` in `TagPicker.cs`): the arrow keys move, Tab or Enter completes the chosen tag (Enter completes rather than saves while the list is open), Escape or a finished tag puts it away, and the Break account is never offered. A note can go on any day: the small calendar beside the box (`NoteDayPick`) picks the day for the next note, shown as a chip (`NoteDayChip`, `NoteDayClear`) until it is added, and a day typed in the words still wins; pressing the date in the header (`DatePick`, `TimerModel.GoToDate`, which on the week views will not pass the current week) opens a calendar that jumps to any day; and Coming up looks 180 days ahead (`TimerModel.ComingUp`). The Missed tab (`TimerModel.MissedNotes`, `MoveMissedToToday`, button `NotesMissedToToday`) lists tasks and deadlines from the last 90 days that were never ticked off, grouped by day, with one button to carry them to today; an event just passes, so it is never missed. Removing a note keeps it for Undo remove (`NoteUndoRemove`, `TimerModel.RestoreRemovedNote`, the last 20). A note the database refuses never crashes the app or leaves the screen: it keeps a negative id and is written again with every save (`NoteStore`, `RetryNoteWrites`, `NotesUnsaved`), with a notice (said again only when its words change). This is kept apart from `LastError`, which the account and entry dialogs read to decide whether their own save failed. Reminders (`Reminders.cs`, `ReminderRules`, `ReminderCard`; `TimerModel.Reminders`, `ActiveReminder`, `SnoozeReminder`, `DoneReminder`, `ReminderDue`, `NotesRequested`): a note with a time, or a `!` deadline (17:00 when it has none), is Soon for the lead time before it (a quiet dot on the Notes rail button, 10 minutes by default, 0 for none), Due for five minutes after (a card with Snooze and Done), then Overdue until ticked off, and it looks back 24 hours so one that fell due while the app was closed still shows. A ticked note never reminds, Snooze (kept in the settings file as `remindsnoozed=id:ticks,...`, so a restart does not bring it straight back) hides it for the snooze time and then it is Due again, and the check runs on every `Tick` and notifies only when the set of states changes. The card is `ReminderCard`: a floating `messageBar` above the message line on the dashboard (red outline when overdue, `late` class), and a row under the capsule in the pill (`reminderHost`, its own grid row, so the pill's width never changes and `WantedHeight` adds its height; the pill becomes a card shape while it shows, `ApplyShape`). Pressing its words opens Notes (`RequestNotes`), and a reminder falling due while the timer is tucked away brings the pill back. Settings, Reminders, holds the on/off switch, heads-up and snooze times (saved as `remind=off`, `remindlead=N`, `remindsnooze=N`). A due reminder plays the system alert sound once (`ReminderSound`, `TimerModel.ReminderSoundOn`, saved as `remindsound=off`, a switch in Settings, Reminders), and restores a timer that was only minimised (`WindowCoordinator.BringBackForReminder`, since a minimised window still counts as visible, which is how the timer is tucked away without a tray). There is no Windows notification. Everything waiting is also one list (`NotificationsPanel` in `Notifications.cs`, built each time its flyout opens and following the model while open): "Needs attention" (overdue, due, and a meeting's "did it take place?") above "Coming up" (heads-ups), each row with its own buttons (`NotificationItem_<id>`, `NotificationSnooze_<id>`, `NotificationDone_<id>`, `NotificationNo_<id>`, `NotificationYes_<id>`). It opens from the bell at the left of the dashboard header's date controls (`NotificationsBell`, with a count badge `NotificationsBadge` that goes red when anything is overdue) and from "+2 more" on a reminder card (`ReminderMore`, which counts the other reminders, `TimerModel.MoreReminders`), so the pill's capsule never gains a button and its width never changes. Snooze on a card and in the list is a drop-down of the Settings choices (`ReminderUi.SnoozeButton`, `ReminderSnooze_<minutes>`, `TimerModel.SnoozeReminder(id, minutes)`), and a meeting's question can be put off the same way (the "…" on the timeline prompt). A heads-up shows on the pill only when Settings, Reminders, "Show a reminder on the pill before it is due" is on (`TimerModel.ShowUpcoming`, saved as `remindupcoming=on`, off by default). While the dashboard shows the timeline (`TimerModel.TimelineVisible`) a meeting's question is drawn on it, under the block (`TimelinePrompt_<id>`, `TimelinePromptNo_<id>`, `TimelinePromptYes_<id>`, `TimelinePromptLater_<id>`), and the floating card (`TimerModel.DashboardReminder`) leaves out that day's question so it is not asked twice. The main action of a panel (Add note, Save) is solid in the accent colour (the `primary` class on a `toolButton`); other buttons keep the quiet outline. A meeting is a note typed with a start and a later end (`14:00 - 15:30`, a hyphen or dash; `DayNote.End`, `DayNotes.IsMeeting`, `end_time` in `day_notes` from format 4 of the shared storage, so it needs `BasicallyGod.Timer.Core` and `Timer.Storage` 0.3.0 or later). It shows as 14:00–15:30 (`NoteTimes.Of`), reminds before it like any timed note, is never Overdue while it is under way, and is drawn on the timeline as planned time (`TimerModel.MeetingsOn`, a dashed outline named `TimelineMeeting_<id>` in its own lane down the right-hand side so tracked time never hides it, never counted in any total). When it ends it asks once, on the usual reminder card, whether it took place (`ReminderState.Followup`, buttons No and Yes on `ReminderSnooze` and `ReminderDone`): No ticks the note off, Yes opens Add time on its hours (only the free part when some of it is already recorded, which stays as it was; none left ticks it off at once) with the account its `#Tag` names chosen (`TimerModel.LogMeeting`, `FreeParts`, `TakeEntryAccountHint`, `EndMeetingLog`), and saving that entry ticks the note off, so the planned block gives way to tracked time. An unanswered question stays until answered, for up to a day. A note repeats when its words hold an `every` phrase (`every day`, `every weekday`, `every mon`, `every mon,wed,fri`, `every week`, `every 2 weeks fri`, each with an optional `until 2026-12-31`; always spelled with "every", never a bare "daily"; `Recurrence` and `NoteSeries` in `Timer.Core`, format 5 of the shared storage, so it needs the packages at 0.4.0 or later). A repeat is a series (the template, its rule and `GeneratedTo`, the last day notes were made for) and ordinary dated notes that carry its id (`DayNote.SeriesId`), made from today up to eight weeks ahead when the note is added, when the app starts and each day (`TimerModel.MakeSeriesNotes`, never filling in the past), so every occurrence can be moved, ticked, answered (a No on a meeting skips only that day) or removed alone, and a removed one is not made again because `GeneratedTo` has passed it. Removing a note that repeats asks Remove this one (`NoteRemoveOne_<id>`, or `NoteDetailsRemoveOne` in Details) or This and all later (`NoteRemoveLater_<id>`, `NoteDetailsRemoveLater`, `RemoveSeriesFrom`, which ends the series the day before, or deletes it when nothing earlier is left). The repeat mark on a row names the rule in its tooltip, and the rule is changed in Details (choosing This and all later). `ClearNoteRepeat` and `ApplyToLater` remain on the model. Clicking a row title opens the shared editor; titles wrap to two lines with an ellipsis and full-title tooltip. Edit and remove icons have reserved space. Meetings use a clock rather than a completion checkbox, deadlines use a flag action, and tasks use checkboxes. The visible filter labels are Meetings and Overdue; existing automation names remain unchanged. Coming up shows a series once, as its next time, and the Missed tab leaves repeats out, since the next one is already there. Renaming or deleting an account follows into the template too.

- Quick capture (`QuickCaptureWindow`, `QuickCapture.cs`) is a small borderless always-on-top box for a note from anywhere, opened by Add note… near the top of the right-click menu (`Ui.SettingsMenu`, name `AddNoteMenu`, followed by a divider that is always showing) or by a shortcut (`TimerModel.RequestQuickCapture`, `QuickCaptureRequested`, handled by `WindowCoordinator.ShowQuickCapture`, one at a time). It takes the Notes shorthand, shows how the words were read (`QuickCaptureWindow.Describe`) and saves through `AddDayNote` on today (or the day it names), so it adds no storage of its own; Enter saves, Escape throws the words away and closes, and clicking away closes but keeps what was typed (`TimerModel.QuickCaptureDraft`, in memory) for the next time the box opens. The shortcut (`HotkeySpec` from `Timer.Core`: Ctrl, Alt or Win plus a letter, digit or F1 to F12, written Ctrl+Alt+N) is set by pressing it in Settings, Quick capture (`CaptureShortcut`, `CaptureShortcutClear`, `CaptureOpen`), kept in the settings file as `capturekey=` through the library's extras (`TimerModel.CaptureShortcut`, `SetCaptureShortcut`; nothing when none, which is the default), and registered on Windows only by `GlobalHotkey` on the first timer window with a handle (a shortcut another app holds gives a notice, and nothing is registered on other systems).

## Lessons from the build

- Notes touched `TimerModel`, `Windows.cs`, `SettingsView`, `ReviewViews`, `Controls`, `Dialogs` and `App.axaml` in many small places, which made it hard to take out. Build the rebuild behind its own types where it can (a `NotesModel` beside `TimerModel`, not inside it).
- The pill, the dashboard column and the timeline each gained a Notes branch. Keep those hooks to one small seam each.
- The shared package already holds the notes model (`DayNote`, `NoteSeries`, `Recurrence`, `NoteShorthand`, storage formats 3 to 6) and the desk app uses it. Reuse it.
- Tests that click through real windows were the flaky ones (hover, settings page, About clicks). Use the helpers in `RobustInput` and `TestPages`.
